## Architecture

Storyteller Studio is a **5W short-form video creator**. Users structure a story as five beats — WHO, WHAT, WHERE, WHEN, WHY — each with a headline, description, and optional media. They pick a visual style (CLEAN, BOLD, CINEMATIC) and preview an animated phone-frame mockup of the video.

### Full-stack layout

The project is a monorepo with a single `package.json`. In development, one Express server on port 5000 serves both the API (`/api/*`) and acts as a Vite dev-server middleware for the React SPA (via `server/vite.ts`). In production, Vite outputs to `dist/public/` and Express serves it statically (`server/static.ts`). The server is bundled by esbuild into `dist/index.cjs`.

```
client/          React SPA (Vite root)
  src/
    pages/       Route-level components (home.tsx is the entire app)
    components/  story-input.tsx, preview-canvas.tsx, ui/ (shadcn)
    lib/         story-types.ts (core domain types), queryClient.ts, utils.ts
server/          Express backend
  index.ts       App setup, logging middleware, port binding
  routes.ts      API route registration (currently empty — add routes here)
  storage.ts     IStorage interface + MemStorage in-memory implementation
  vite.ts        Vite middleware wiring for dev
  static.ts      Static file serving for production
shared/
  schema.ts      Drizzle/PostgreSQL schema + Zod insert schemas (User)
script/
  build.ts       Orchestrates Vite + esbuild production build
attached_assets/ Static images referenced at build time via @assets alias
```

### Data flow

- **Domain types** live in `client/src/lib/story-types.ts` (`StoryBeat`, `MotionStyle`, `INITIAL_STORY`). These are purely client-side; the server schema (`shared/schema.ts`) only defines `users` so far.
- **State** is managed locally in `home.tsx` via `useState` — no global store, no server persistence for story data yet.
- **API calls** use the `apiRequest` helper in `queryClient.ts` and TanStack Query for data fetching.
- **Storage abstraction**: `IStorage` in `server/storage.ts` defines the CRUD interface. The exported `storage` singleton is currently `MemStorage`. To switch to PostgreSQL, implement `IStorage` against Drizzle and swap the export — routes consume only `storage`, not a concrete class.

### UI

- Components use **shadcn/ui** (Radix primitives + Tailwind) in `client/src/components/ui/`.
- Animations are handled by **Framer Motion** (`motion`, `AnimatePresence`).
- `PreviewCanvas` renders a phone-frame mock with three animation variant sets keyed by `MotionStyle`.
- `StoryInput` expands inline (accordion-style) when a beat is active.
- Routing uses **wouter** (`Switch`/`Route`).
- Tailwind CSS v4 is configured via `@tailwindcss/vite` (no `tailwind.config.js`).

### Database

- Schema: `shared/schema.ts` using Drizzle ORM with PostgreSQL dialect.
- Requires `DATABASE_URL` env var. Without it, `db:push` and any DB-backed storage will throw.
- Run `npm run db:push` to sync schema changes to the database (no migration files generated by default; use `drizzle-kit generate` for migration files if needed).
